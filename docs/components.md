# コンポーネント要件

開発者向けの実装対象の棚卸し。採用する公開 UI コンポーネントの正式名称は以下の Pomme 接頭辞付きの名称とする。検討対象の採否、公開関数のシグネチャや DSL、内部実装単位は未確定。

## 入力系

| 公開コンポーネント名 | 必要な機能・責務 |
| --- | --- |
| PommeButton | テキスト・アイコンによる操作、標準的なボタン外観、無効状態、必要に応じた破壊的操作の表現 |
| PommeTextField | 単一行テキスト入力、プレースホルダー、フォーカス、IME、入力値の変更 |
| PommeSecureField | パスワード等の秘匿入力、通常の入力制御との整合 |
| PommeTextEditor | 複数行のテキスト入力、長文とスクロールへの対応 |
| PommeToggle | ON/OFF の状態表示と変更、無効状態 |
| PommePicker | 選択肢の表示と単一選択、既存画面に必要な選択形式（メニュー、セグメント等）の検討 |
| PommeDatePicker | 日付・時刻の選択、必要な選択範囲・表示形式への対応 |
| PommeSlider | 範囲内の数値入力、現在値の表示・操作 |
| PommeStepper | 数値の増減。実際の利用要件を確認して採否を決める |

テーマは PommeTheme、カラースキームは PommeColorScheme とする。

入力値の正本は利用側。入力コントロールには業務上の保存処理、検証ルール、確認ダイアログ等を組み込まない。

## リスト系

| 公開コンポーネント名 | 必要な機能・責務 |
| --- | --- |
| PommeList | リスト全体の背景、スクロール、セクション間の配置・余白、長いデータ集合への対応 |
| PommeForm | 入力を主目的としたリスト表示。グループ化された背景と Section の利用 |
| PommeSection | ヘッダー・フッター、行のグループ化、セクション背景、角丸、行間の区切り線 |
| PommeRow | 行内の要素配置、共通の余白とタップ領域、必要な場合の操作や補助表示 |

通常のリスト（Plain）と、左右に余白を持つグループ化されたリスト（Inset Grouped）に相当する外観を初期対象とする。具体的なスタイル指定方法、ヘッダー・フッターの構造、行の DSL 等は詳細設計で決める。

PommeRow は内容を組み合わせられる汎用的な構造を優先する。用途ごとに同じ装飾を再実装した行を増やさない。タップ可能な全ての行にナビゲーションを示す Chevron を自動付与しない。行内に入力コントロールが存在する場合は操作競合や二重イベントを防ぐ。

PommeForm / PommeList / PommeSection は Compose の Scope を活用した宣言的な構成を目指し、静的・動的な行の構成、条件による表示、親の装飾管理を扱えるように設計する。詳細は [Scope を活用した設計方針](architecture.md#scope-を活用した宣言的-ui-の設計方針) を参照する。

## スクリーン系

| 公開コンポーネント名 | 必要な機能・責務 |
| --- | --- |
| PommeScaffold | 画面背景、上部・下部のバーとコンテンツ領域の配置、システムバー・IME・WindowInsets との整合 |
| PommeToolbar | 画面タイトル、前後の操作領域、タイトルと操作の配置、必要な操作要素の外観 |

PommeScaffold / PommeToolbar は Scope を活用して画面構造と操作要素の配置意図を宣言できるようにする。具体的な DSL は詳細設計で決める。地図等の独自コンテンツにも適用できること。画面遷移、戻る可否、保存可否は利用側が判断する。保存・キャンセル・戻るボタンなどの自動追加を行わない。Android のシステム戻る操作を不必要に奪わない。

## その他の検討対象

- PommeAlert / PommeConfirmationDialog：標準的な通知・確認・選択肢の表示。
- アイコン：既存の Cupertino アイコン依存を解消できる汎用的な代替。権利上利用可能な素材を用いる。
- PommeProgressView：既存利用箇所を精査し必要な表示を提供する。
- PommeSheet：必要な場合に限り表示コンポーネントとして検討し、ルーティングは利用側に残す。

これらの採否・優先度は既存利用箇所と汎用性の要件を踏まえて決定する。MaTool_Kotlin の依存箇所全体の照合は別途必要。

## 共通の受け入れ条件

各 UI コンポーネントで、テーマへの追従、表示と入力の基本挙動、必要なアクセシビリティ、適切なサイズ・余白、Compose Preview を確認する。該当する主要状態（選択済み・未選択、無効、空・入力済み等）を Preview で確認できること。詳細仕様の確定後に個別の受け入れ条件を追加する。
